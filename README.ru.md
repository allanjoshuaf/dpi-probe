# dpi-probe

[English](README.md) | [Français](README.fr.md) | [Русский](README.ru.md) | [简体中文](README.zh.md)

**1.0.0-beta.1** представляет собой набор сетевых диагностических тестов в терминале: DNS, TCP, TLS/SNI, HTTP Host, ECH, сбросы соединений, сегментация и сравнение путей. Диагностика VLESS/REALITY является отдельным специализированным модулем.

Инструмент собирает наблюдения, показывает этап сбоя, возможные объяснения и необходимые дополнительные проверки. Тайм-аут не доказывает наличие DPI. Пакет RST не определяет его отправителя. Две записи трафика позволяют ограничить участок расхождения точками наблюдения, но не назвать конкретный фильтрующий маршрутизатор.

## Для каких случаев

| Ситуация | Что можно проверить |
|---|---|
| Через мобильную сеть работает, дома нет | Сравнить DNS, TCP и TLS при одинаковых целях и параметрах. |
| Подозрение на подмену DNS | Сопоставить локальные и контрольные ответы с учётом CDN и недоступности контрольных резолверов. |
| TCP устанавливается, TLS зависает | Изменять SNI, поля TLS и разбиение записей TCP, наблюдать ответы. |
| Нужна проверка ECH | Отдельно проверить DNS HTTPS и запрос, который требует ECH в совместимой сборке curl. |
| Сбросы и односторонняя передача | Исследовать диапазоны TCP sequence, ACK и порядок FIN/RST в клиентской и серверной записи. |
| Не работает VLESS/REALITY | Сопоставить конфигурацию sing-box, журналы, маршрут и записи трафика. |

## Установка и запуск

Скачайте и распакуйте репозиторий. В Windows откройте **`dpi-probe.cmd`**, в Linux выполните **`sh dpi-probe.sh`** из каталога проекта.

Программа установки проверяет Python 3.11+, предлагает создать `.venv` и установить `requirements.txt`, затем проверяет TShark и интерфейсы захвата. Каждая установка требует ответа пользователя. В Windows предлагаются Python 3.13 и Wireshark через winget; завершите интерактивную установку, включая TShark и Npcap. Если winget отсутствует, установите Python с официального сайта и повторите запуск. Для Debian/Ubuntu используется apt, когда он доступен; для других систем выводятся ручные инструкции. Могут понадобиться права администратора.

Обязательные Python-модули: `cryptography` и `dnspython`. Отсутствующие или несовместимые версии блокируют запуск. Без TShark можно выполнять тесты без захвата; явный запрос захвата при отсутствии необходимых средств завершается ошибкой. Отсутствие зависимости никогда не считается признаком фильтрации. Графический Wireshark удобен для просмотра, автоматизация использует TShark.

| Возможность | Требования |
|---|---|
| Меню, основные тесты, отчёты | Python 3.11+, venv/pip, requirements.txt |
| Анализ PCAP | TShark |
| Захват трафика | TShark, Npcap в Windows или libpcap в Unix, разрешения |
| Активный ECH | Сборка curl с поддержкой `--ech hard` |
| Обратная трассировка | SSH и подконтрольный удалённый узел с traceroute/tracert |

Ручная установка в Windows:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python main.py --doctor
.venv\Scripts\python main.py
```

В Linux создайте окружение командой `python3 -m venv .venv`, затем используйте `.venv/bin/python`. При необходимости установите пакет venv/pip вашей системы. `--doctor` проверяет локальные зависимости без сетевых проб; код 2 означает отсутствие основных средств или средств захвата. Наличие интерфейса в списке не гарантирует разрешение захвата.

Windows проверяется локально; Linux включён в CI. Полевые испытания на реальном оборудовании Linux/OpenWrt ещё нужны. На OpenWrt предпочтительна короткая запись tcpdump с анализом на компьютере. Полная установка на маршрутизатор экспериментальна и зависит от памяти, архитектуры и пакетов. Установщик не меняет маршруты и межсетевой экран.

## Меню

При первом запуске выберите английский, французский, русский или упрощённый китайский. Пункт 6 меняет язык; в пользовательских настройках сохраняется только его код. Меню и поля ввода переведены, технический вывод и отчёты переведены не полностью. Установка пока использует английский/французский.

1. Общая диагностика: быстрая, полная или отдельные тесты; необязательный захват для полного запуска.
2. Диагностика VLESS/REALITY.
3. Расширенные средства: две записи, пассивный/активный ECH, интерфейсы.
4. Сравнение подробных отчётов.
5. Сокращённый экспорт для добровольной публикации.
6. Язык; 0 завершает работу.

Полный запуск проверяет TCP/443, HTTP, SNI, TTL, RST, некорректный TLS, различия адресов назначения, HTTP Host, DNS, сегментацию записей TCP, варианты TLS, отпечатки специально сформированного ClientHello, мутации TLS и публикацию ECH. Исторические названия модулей «bypass» и «fragmentation» не означают подтверждённый обход на уровне приложения или фрагментацию IP. Запуск может длиться несколько минут. `--samples` повторяет только тесты с поддержкой выборки.

## Команды

Используйте Python из окружения. Запуск без аргументов требует терминала; `--auto` явно включает быстрый автоматический режим.

```text
python main.py --help
python main.py --version
python main.py --auto
python main.py 1.1.1.1 --samples 3 --profile direct
python main.py 1.1.1.1 --samples 3 --profile alternate --pcap --pcap-interface 3
python main.py --multi --samples 3
python main.py --compare reports/direct.json reports/alternate.json
python main.py --ech example.com
python main.py --ech example.com --ech-active
python main.py --anonymize reports/direct.json
```

Замените 3 номером из списка интерфейсов. Захват полного запуска ограничен портом 443 цели, а не всеми DNS-запросами и адресами. `targets.json` задаёт IPv4-цели и группы доменов. Публичные anycast-цели по умолчанию не подконтрольны проекту и не являются авторитетными TLS-серверами для любого SNI. Группы `blocked`/`clean` не доказывают блокировку. Для обоснованного вывода используйте подконтрольные узлы и разрешённые активные тесты.

Активный ECH использует curl с `--ech hard`, Cloudflare DoH, проверкой сертификата и без HTTP-прокси из окружения. Успех, отсутствие поддержки, невыполненное требование ECH и ошибка транспорта различаются. Маршрут через TUN сохраняет влияние. Публикация DNS не доказывает принятие ECH; неудача ECH не доказывает фильтрацию.

### Туннель и две записи трафика

```text
python main.py --diagnose-tunnel --sing-box-config config.json --outbound-tag reality --sing-box-log client.log --tunnel-endpoint SERVER_IP:443 --tunnel-pcap client.pcapng --server-pcap server.pcapng --diagnosis-output reports/incident.json
python main.py --dual-pcap client.pcapng server.pcapng --tunnel-endpoint SERVER_IP:443 --flow-output reports/paired.json
tshark -D
tshark -i 3 -f "host SERVER_IP and tcp port 443" -a duration:30 -w client.pcapng
tcpdump -i any -s 0 -w server.pcap 'tcp port 443'
```

Замените параметры примера; необязательные отсутствующие файлы исключите. Выбранный outbound должен иметь уникальный tag. Для старой записи укажите фактический IP сервера в момент сбоя. Запишите одну и ту же попытку с двух сторон, синхронизировав часы. При захвате из меню соединение воспроизводится существующим клиентом. dpi-probe не выполняет аутентификацию REALITY: обычный успешный TLS может быть ответом fallback.

`--active-tunnel-checks` добавляет TCP и трассировку. В Windows `--underlay-interface-index N` выбирает физический интерфейс для TCP-пробы; его системный индекс отличается от номера TShark. Снимок маршрутов не подтверждает обход TUN всеми пробами. Локальное API: `--sing-box-api http://127.0.0.1:9090 --sing-box-secret-env VARIABLE_NAME`; удалённые URL и перенаправления запрещены.

Обратная трассировка требует вашего удалённого агента:

```text
python main.py --reverse-trace PUBLIC_IP --reverse-agent probe@CONTROLLED_HOST
```

## Отчёты и ограничения

Подробные общие и туннельные отчёты сохраняются в JSON и Markdown. Быстрые проверки, ECH и сравнение записей используют отдельные форматы, не все из которых принимает сравнитель подробных отчётов. По умолчанию файлы находятся в `reports/`. Автоматической отправки и постоянного мониторинга нет.

NAT, асимметрия, offload, неполные записи и потери захвата влияют на выводы. Сопоставление использует TCP-признаки и диапазоны sequence, не проверяя подлинность содержимого. Отсутствующие диапазоны не являются измеренным процентом потерь сети.

PCAP, конфигурации и журналы могут содержать адреса, домены и секреты. Маскирование распространённых секретов не универсально. Сокращённый туннельный экспорт сохраняет диагностические коды, общий экспорт по-прежнему содержит проверенные домены. Проверьте файл перед публикацией. Git игнорирует отчёты, журналы, записи трафика и окружения.

## Проверка и статус

```text
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m coverage run --source=src -m pytest -q
python -m coverage report --omit="src/probes/*" --fail-under=40
python -m compileall -q main.py bootstrap.py src
python main.py --help
git diff --check
```

Тесты покрывают схемы, регрессии, меню, языки и синтетические PCAP через настоящий TShark, если он установлен. Недоступные необязательные интеграции явно пропускаются. Это не подтверждает точность у каждого провайдера. Статус beta сохраняется до контролируемых полевых испытаний, расширенной проверки установки и вычитки носителями языка.
